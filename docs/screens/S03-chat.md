# S03 チャット画面

## 1. 概要

| 項目 | 内容 |
|---|---|
| 画面ID | S03 |
| 画面名 | チャット画面 |
| パス | `/chats/{chat_id}` |
| 認証 | 必要 |

対応する画面一覧は [screen-list.md](../screen-list.md)、画面遷移は [screen-flow.md](../screen-flow.md) を参照。画面内の状態遷移（生成中／待機中）は [screen-flow.md](../screen-flow.md) 3節で定義済みのため、本書はそれをベースに画面仕様へ落とし込む。

## 2. 画面の目的

選択済みのペルソナ（複数体）とユーザーが会話する。`chat_mode` に応じて、ユーザー参加型の会話、またはペルソナ同士の自動会話を閲覧・制御する。

## 3. 想定ユーザー

ログイン済みユーザーのうち、当該チャットを作成した本人（[api.md](../api.md) の認可仕様を参照）。

## 4. 表示内容

- **ヘッダー**：チャットタイトル、参加ペルソナ一覧（肖像画像）。`chat_mode` が `USER_PARTICIPATED` の場合は「あなた」も含める（S02と同様の考え方）。
- **メッセージ一覧**：吹き出し形式。発言者アイコン（肖像画像／ユーザー）＋名前を添えて表示する。ユーザー発言は右寄せ、ペルソナ発言は左寄せとする。
- **画面下部の操作エリア**：`chat_mode` により表示が異なる。
  - `USER_PARTICIPATED`：メッセージ入力欄＋送信ボタン。応答生成中は入力欄・送信ボタンを非活性にし、別途「停止」ボタンのみを活性化する。
  - `PERSONA_ONLY`：入力欄は表示せず、「開始」／「停止」ボタンのみを表示する（状態に応じていずれか一方を活性化）。
- **空データ**：メッセージが1件もない場合、モードに応じた案内文言を表示する。
- **レート制限中の案内**：送信不可の理由メッセージ。

## 5. UIコンポーネント

| コンポーネント | 種別 | 備考 |
|---|---|---|
| ヘッダー | ヘッダー | チャットタイトル＋参加ペルソナ一覧（肖像画像。`USER_PARTICIPATED`時は「あなた」も含む） |
| メッセージ吹き出し | bubble | 発言者アイコン＋名前を併記。ユーザー発言は右寄せ、ペルソナ発言は左寄せ |
| ストリーミング中の吹き出し | bubble | 受信したチャンクを逐次追記して表示する（タイピング風） |
| メッセージ入力欄 | textarea | `USER_PARTICIPATED` の場合のみ表示。最大500文字 |
| 送信ボタン | button | `USER_PARTICIPATED` の場合のみ表示。生成中は非活性 |
| 停止ボタン | button | 生成中／自動進行中のみ活性。送信ボタンとは別ボタンとして常に存在する |
| 開始ボタン | button | `PERSONA_ONLY` の場合のみ表示。停止中のみ活性 |
| エラー・案内メッセージ | alert/banner | 空データ・レート制限・通信エラー等の案内に使用 |

## 6. ユーザー操作

### USER_PARTICIPATED モード

- 入力欄にメッセージを入力し、送信ボタンを押す。送信されたユーザー発言が即座に一覧へ追加され、ペルソナ応答の生成が始まる。
- 応答生成中（連鎖発言を含む）は入力欄・送信ボタンが非活性になり、停止ボタンのみ操作できる。停止ボタンを押すと生成中の応答を中断し、入力待ち状態に戻る。

### PERSONA_ONLY モード

- 「開始」ボタンを押すと、ペルソナ同士の自動会話が始まる。開始後は開始ボタンが非活性（または非表示）になり、停止ボタンが活性になる。
- 「停止」ボタンを押すと自動進行を中断し、停止中の状態に戻る。

## 7. バリデーション

| 項目 | ルール |
|---|---|
| メッセージ本文（`USER_PARTICIPATED`） | 空送信不可、最大500文字 |
| 送信頻度（レート制限） | ユーザー単位（全チャット横断）で、直近1分間に10回、1日あたり50回を超える送信・開始操作を制限する |

- レート制限に該当する間は、送信ボタン（`PERSONA_ONLY` の場合は開始ボタン）を無効化し、理由メッセージ（短時間制限／1日の上限のいずれに該当するかが分かる文言）を表示する。
- フロントエンドで文字数・空送信のチェックを行い、レート制限の判定はAPI（[api.md](../api.md)）側の応答（429）に従う。

## 8. 状態遷移

[screen-flow.md](../screen-flow.md) 3節の状態図に対応する。

### 共通

- **読込中**：画面表示時、メッセージ履歴取得中はローディング表示にする。
- **空データ**：メッセージが1件もない場合、モードに応じた案内文言を表示する（`USER_PARTICIPATED`：「メッセージを送ってみましょう」、`PERSONA_ONLY`：「開始ボタンを押して会話を始めましょう」）。
- **Not Found**：`chat_id` が存在しない、削除済み、または他ユーザーが作成したチャットである場合（API 404／403）、エラー画面は表示せずS02 チャット履歴画面へ自動的にリダイレクトする。他ユーザーのチャットであることを画面上で判別させないため、404と403は区別せず同じ挙動とする。
- **レート制限中**：送信／開始ボタンを無効化し、理由を表示する。
- **エラー**：Not Found以外の通信エラー（500等）やSSE切断が発生した場合は、自動リダイレクトはせずエラーメッセージを表示し、操作可能な状態に戻す。

### USER_PARTICIPATED

- **入力待ち**：入力欄・送信ボタンが活性、停止ボタンは非活性。
- **ペルソナ応答生成中**：入力欄・送信ボタンが非活性、停止ボタンが活性。ストリーミング中は吹き出しに文字が逐次追加される。連鎖発言時も同じ状態を維持し、発言が完了するたびに新しい吹き出しが追加される。
- **入力待ちへ復帰**：連鎖の有無を問わず応答が完了した場合、またはユーザーが停止操作を行った場合。

### PERSONA_ONLY

- **停止中**：開始ボタンが活性、入力欄は表示しない。
- **自動進行中**：開始ボタンが非活性、停止ボタンが活性。ストリーミングで発言が追加され続ける。
- **停止中へ復帰**：ユーザーが停止操作を行った場合。

## 9. 画面遷移

- S02 チャット履歴画面の「Open」ボタン、またはS01 新規チャット画面での作成成功から本画面へ遷移する（[screen-flow.md](../screen-flow.md) 参照）。
- 本画面自体はページ遷移の末端であり、他画面への直接的な遷移導線は持たない。
- `chat_id` が存在しない／削除済み／他ユーザーのチャットである場合 → S02 チャット履歴画面へ自動リダイレクト（8節参照）。
- 共通サイドバーから他画面（新規チャット／チャット履歴／ペルソナ一覧／ログアウト）へいつでも遷移できる（[screen-list.md](../screen-list.md) 3節）。離脱時、進行中のストリーミング表示は破棄される。次に本画面を開いたときは常にメッセージ履歴の取得（GET）から始まり、SSEへの自動再接続は行わない（10節・12節参照）。

## 10. APIとの入出力

対応API: [api.md](../api.md)

### メッセージ一覧取得

```http
GET /chats/{chat_id}/messages
```

画面表示時に、既存のメッセージ履歴を取得する。`chat_id` が存在しない、削除済み、または他ユーザーが作成したチャットの場合は404／403を返す（8節・9節参照）。

### メッセージ送信（会話進行トリガー）

```http
POST /chats/{chat_id}/messages
```

- `USER_PARTICIPATED`：送信ボタン押下時に、ユーザー発言をリクエストボディに含めて呼び出す。レスポンスはSSEでペルソナ応答をストリーミング配信する。
- `PERSONA_ONLY`：開始ボタン押下時に、リクエストボディなしで呼び出す。レスポンスはSSEでペルソナ同士の発言を継続的にストリーミング配信する。

レート制限超過時は429を返す（7節参照）。

### 会話停止

```http
POST /chats/{chat_id}/stop
```

停止ボタン押下時に呼び出す。自動進行中・連鎖発言中の会話を即座に中断する。

フィールド名・ステータスコード等の詳細は実装時に確定し、[api.md](../api.md) との整合を取ること。

## 11. 権限制御

ログイン必須画面。ログインユーザー自身が作成したチャット（`t_chat.user_id` が一致するもの）のみ閲覧・操作可能とする。他ユーザーが作成したチャットへのアクセスは403とする（[api.md](../api.md) 参照）。

## 12. その他実装上の注意事項

- レート制限（1分間に10回、1日50回）はユーザー単位で全チャット横断のカウントとする（悪用・コスト対策。[要件定義書](../requirements-definition.md) 7節参照）。
- メッセージ本文の最大500文字は、フロントエンド・バックエンドの双方でチェックする。
- `PERSONA_ONLY` の自動進行は、画面を離れた後もサーバー側では継続している可能性がある。本画面を再度開いた際は常にメッセージ履歴の取得（GET）のみを行い、SSEへの自動再接続は行わない。会話を継続する場合は、ユーザーが改めて「開始」ボタンを押す。
- ストリーミング中の吹き出しは、SSEで受信したチャンクを逐次追記して表示する。
- 新着メッセージ受信時は常に最下部へ自動スクロールする。
