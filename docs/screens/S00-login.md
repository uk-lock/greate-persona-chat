# S00 ログイン画面

## 1. 概要

| 項目 | 内容 |
|---|---|
| 画面ID | S00 |
| 画面名 | ログイン画面 |
| パス | `/login` |
| 認証 | 不要 |

対応する画面一覧は [screen-list.md](../screen-list.md)、画面遷移は [screen-flow.md](../screen-flow.md) を参照。

## 2. 画面の目的

ログインID・パスワードによりユーザーを認証し、ログイン後のトップ画面（S02 チャット履歴画面）へ遷移させる。

## 3. 想定ユーザー

管理者が発行したアカウントを保有する、未ログイン状態でアクセスした全ユーザー。

## 4. 表示内容

- アプリ名（タイトル表示）
- アプリの簡単な説明文（1文程度のキャッチコピー）
- ログインフォーム
  - ログインID入力欄
  - パスワード入力欄（平文表示切替アイコン付き）
  - ログインボタン
- サインアップへのリンク（フォーム下部。サインアップ機能が有効な場合のみ表示。11節参照）
- エラーメッセージ表示領域（フォーム上部）

## 5. UIコンポーネント

| コンポーネント | 種別 | 備考 |
|---|---|---|
| アプリ名／説明文 | テキスト | 静的表示 |
| ログインIDラベル＋入力欄 | text input | 必須 |
| パスワードラベル＋入力欄 | password input | 必須。目のアイコンで平文表示を切替可能 |
| ログインボタン | button | 送信中はローディング表示＋無効化 |
| サインアップへのリンク | link | サインアップ機能が有効な場合のみ表示。押下でS06へ遷移 |
| エラーメッセージ | alert/banner | フォーム上部。認証失敗時のみ表示 |

## 6. ユーザー操作

- ログインID・パスワードを入力する。
- パスワード欄の目のアイコンをクリックすると、平文表示／非表示を切り替える。
- ログインボタン押下、または入力欄でのEnterキー押下でログイン処理を実行する（一般的なフォーム挙動として想定。異なる場合は要修正）。

## 7. バリデーション

| 項目 | ルール | エラーメッセージ例 |
|---|---|---|
| ログインID | 必須、最大255文字 | 未入力時「ログインIDを入力してください」 |
| パスワード | 必須、最大255文字 | 未入力時「パスワードを入力してください」 |

- 文字数上限は `m_user.login_id` / `password_hash` の `VARCHAR(255)` 定義（[db.md](../db.md)）に合わせる。
- フロントエンドでは必須・文字数上限のみを検証し、ID・パスワードの組み合わせが正しいかどうかの検証は API（`POST /auth/login`）に委ねる。

## 8. 状態遷移

- **初期表示**：フォーム入力可能、ログインボタン活性。
- **送信中**：ログインボタンをローディング表示にし、入力欄・ボタンを無効化して二重送信を防止する。
- **エラー（認証失敗）**：フォーム上部に汎用エラーメッセージ「ログインIDまたはパスワードが正しくありません」を表示し、入力可能状態に戻す（パスワード欄は空にする）。
- **ロック中**：同一ログインIDで連続10回認証に失敗すると、以後15分間はログイン試行を受け付けない。専用メッセージ「ログイン試行回数が上限に達しました。15分後に再度お試しください。」をフォーム上部に表示する。15分経過後は自動的に解除され、初期表示状態に戻る。
- **成功**：S02へ遷移するため、本画面上での状態保持は不要。

## 9. 画面遷移

- 認証成功 → S02 チャット履歴画面（`/chats`）
- 有効なセッション（JWT Cookie）を保持した状態で `/login` にアクセスした場合 → ログインフォームを表示せず、自動的にS02へリダイレクトする。
- サインアップへのリンク押下 → S06 サインアップ画面（`/signup`）。サインアップ機能が無効な場合、このリンクは表示しない（11節参照）。

## 10. APIとの入出力

対応API: [api.md](../api.md) の「ログイン」（`POST /auth/login`）

### リクエスト

```json
{
  "login_id": "string",
  "password": "string"
}
```

### レスポンス（想定）

- 成功時（200）：JWTをHttpOnly Cookieに設定。レスポンスボディは最小限とし、フロントはCookie設定を前提にS02へ遷移する。認証成功に伴い、サーバー側で失敗回数カウントを0にリセットする。
- 認証失敗時（401）：

```json
{
  "message": "ログインIDまたはパスワードが正しくありません"
}
```

- ロック中（423）：

```json
{
  "message": "ログイン試行回数が上限に達しました。15分後に再度お試しください。"
}
```

フィールド名・ステータスコード等の詳細は実装時に確定し、[api.md](../api.md) との整合を取ること。

## 11. 権限制御

未ログイン専用画面。有効なセッションを保持するユーザーがアクセスした場合は、ログインフォームを表示せずS02へリダイレクトする（8節・9節を参照）。

サインアップへのリンクは、設定（フラグ）でサインアップ機能自体が無効化されている場合は表示しない。フラグの詳細・S06側の無効化時の挙動は [S06-signup.md](./S06-signup.md) の11節を参照。

## 12. その他実装上の注意事項

- 同一ログインIDでの認証失敗が連続10回に達した場合、当該ログインIDを15分間ロックする（ブルートフォース対策）。ロックは時間経過により自動解除し、管理者による手動解除は設けない。
- 失敗回数カウントは、ログイン成功時、またはロックの自動解除時にリセットする。
- ロック状態・失敗回数の判定はサーバー側で行う（`m_user.failed_login_count` / `m_user.locked_until`、[db.md](../db.md)参照）。
- 認証失敗時は、ログインID・パスワードのどちらが誤りかを区別しない汎用メッセージとする（アカウント存在有無を推測されないためのセキュリティ配慮）。ロック中である旨は12節記載の専用メッセージで明示する（ロックの事実自体は秘匿しない）。
