# 要件定義書

## 1. アプリの概要

偉人・著名人物の情報をもとにペルソナを生成し、その人物と対話できるアプリケーション。

- 単なる1対1チャットアプリではなく、複数のペルソナを同一チャットに参加させ、掛け合いを楽しむことができる。
- 対話形式は**テキストチャットのみ**（音声等は対象外）。
- ペルソナの対象人物は、実在の歴史上人物に加え、**架空・フィクションの人物も含む**。
  - 「偉人」という呼称は実在の歴史上人物を想起させるため、詳細設計・画面文言では「ペルソナ」「著名人物」等、より広い呼称を用いることを推奨する。
- 現時点では個人利用が中心だが、**将来的な一般公開も視野**に入れる（ユーザー管理機能を備える）。

## 2. 開発目的・背景

- **技術学習・ポートフォリオ**：LLMを活用したフルスタック開発の学習。
- **将来的に他ユーザーにも使ってもらいたい**：個人利用に閉じず公開も視野に入れる。
- 発想の背景として、**SDD（仕様駆動開発）や設計重視の開発プロセスを実践すること自体**が目的の一つ。

## 3. 想定ユーザー

- キャラクター（ペルソナ）会話を楽しみたい人
- 開発者自身（ドッグフーディング目的）
- ITリテラシー：特に問わない（一般ユーザー向けの分かりやすさを想定）

## 4. 解決したい課題

- 汎用LLMチャット（ChatGPT等）は無色で個性がなく、特定の人物らしい会話がしづらい。
- 複数のキャラクターが掛け合う体験を手軽に作れる場がない。

## 5. 提供したい価値

- キャラの個性がきちんと出た会話体験。
- 複数キャラの掛け合いを見る面白さ。

## 6. 機能要件

### 6.1 ユーザー・認証

- ログインID / パスワードによるログイン機能。
- ユーザーが自身でアカウントを作成できる**セルフサインアップ機能**を提供する（管理者による事前発行に加え、セルフサインアップでもアカウントを作成可能とする）。
  - サインアップ後は追加のログイン操作を挟まず、そのままログイン状態としてアプリを利用開始できる（自動ログイン）。
  - サインアップ導線（ログイン画面のリンク／サインアップ画面自体へのアクセス）は、設定により**有効・無効を切り替え可能**とする。無効時はリンクを非表示にするだけでなく、サインアップ画面への直接アクセスも無効化する。

### 6.2 ペルソナ管理

- MVPでは、ペルソナデータは**管理者がDBに直接投入**する（管理画面は用意しない）。
- 一般ユーザーはペルソナの**閲覧のみ**（作成・編集不可）。
- ペルソナ一覧は、ペルソナ名によるキーワード検索（部分一致）に対応する。国・年代など複合条件による絞り込みは対象外。
- 将来拡張：外部情報取得 → 要約 → ペルソナ自動生成のバッチ処理によるデータ蓄積の自動化。

### 6.3 チャット

- チャット作成時、ペルソナを**2〜4体**まで選択可能（上限を設ける）。
- チャットモードは2種類。
  - `PERSONA_ONLY`（ペルソナ同士のみの会話）
    - 開始すると自動的に連続で会話が進行し、ユーザーは停止ボタンで中断できる。
  - `USER_PARTICIPATED`（ユーザー参加型）
    - ユーザーの発言に対し、参加ペルソナの中から**文脈に応じてLLMが応答するペルソナを選択**する。
- チャットのタイトルは、会話内容から**LLMが自動生成**する。
- チャット一覧の取得・チャットの削除機能を提供する。

### 6.4 メッセージ

- メッセージ一覧の取得機能を提供する。
- ペルソナの応答は**逐次ストリーミング表示**する。

## 7. 非機能要件

- **実行環境**：クラウド（AWS/GCP等）にデプロイし外部公開する。
- **性能**：小規模想定（同時数十人程度）。大規模アクセスへの対応は不要。
- **LLM**：対話生成には OpenAI API を利用する。
- **悪用・コスト対策**：レート制限（連続送信・短時間での連発送信の制限）を設ける。LLM利用料はできるだけ低コストに抑える。
- **対応デバイス**：PC・スマートフォンの両方で快適に使えること（レスポンシブ対応）。
- **運用**：最小限（本格的な監視・冗長化・自動バックアップ体制は不要）。ログで状況確認できれば十分。

## 8. 制約条件

- 技術スタックは以下の通り確定。
  - フロントエンド：Next.js / React / TypeScript
  - バックエンド：FastAPI / Python
  - DB：PostgreSQL
  - 開発環境：Docker Compose / devContainer
- 開発期間・予算：特に期限なし（マイペースで進める）。
- LLM APIの利用料金は、できるだけ低コストに抑えたい。

## 9. 今回の対象外

- 音声による対話（テキストのみ）
- ユーザー自身によるペルソナの作成・編集
- ペルソナ管理用の管理画面（UI）（MVPはDB直接投入で対応）
- 外部情報取得・要約・ペルソナ自動生成のバッチ処理（将来拡張として位置づけ）
- ペルソナ一覧の複合条件（国・年代等）による絞り込み機能（ペルソナ名によるキーワード検索は対応）
- 大規模アクセス対応、本格的な監視・冗長化・自動バックアップ体制
