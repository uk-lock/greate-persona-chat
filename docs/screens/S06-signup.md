# S06 サインアップ画面

## 1. 概要

| 項目 | 内容 |
|---|---|
| 画面ID | S06 |
| 画面名 | サインアップ画面 |
| パス | `/signup` |
| 認証 | 不要 |

対応する画面一覧は [screen-list.md](../screen-list.md)、画面遷移は [screen-flow.md](../screen-flow.md) を参照。

## 2. 画面の目的

新規ユーザーが自身でログインID・パスワードを設定してアカウントを作成する（セルフサインアップ）。登録完了と同時に自動的にログイン状態とし、追加のログイン操作なしにS02 チャット履歴画面へ遷移させる。

## 3. 想定ユーザー

未ログイン状態でアプリの利用を新たに開始したい全ユーザー。

## 4. 表示内容

- アプリ名（タイトル表示）
- サインアップフォーム
  - ログインID入力欄
  - パスワード入力欄（平文表示切替アイコン付き）
  - パスワード確認入力欄（平文表示切替アイコン付き）
  - サインアップボタン
- ログイン画面へのリンク
- エラーメッセージ表示領域（フォーム上部）

## 5. UIコンポーネント

| コンポーネント | 種別 | 備考 |
|---|---|---|
| アプリ名 | テキスト | 静的表示 |
| ログインIDラベル＋入力欄 | text input | 必須 |
| パスワードラベル＋入力欄 | password input | 必須。目のアイコンで平文表示を切替可能 |
| パスワード確認ラベル＋入力欄 | password input | 必須。目のアイコンで平文表示を切替可能 |
| サインアップボタン | button | 送信中はローディング表示＋無効化 |
| ログイン画面へのリンク | link | 押下でS00へ遷移 |
| エラーメッセージ | alert/banner | フォーム上部。登録失敗時のみ表示 |

## 6. ユーザー操作

- ログインID・パスワード・パスワード確認を入力する。
- パスワード欄・パスワード確認欄それぞれの目のアイコンをクリックすると、平文表示／非表示を切り替える。
- サインアップボタン押下、または入力欄でのEnterキー押下で登録処理を実行する。
- ログイン画面へのリンク押下でS00へ遷移する。

## 7. バリデーション

| 項目 | ルール | エラーメッセージ例 |
|---|---|---|
| ログインID | 必須、最大255文字、半角英数字のみ（記号・日本語等のマルチバイト文字不可） | 未入力時「ログインIDを入力してください」／文字種違反時「ログインIDは半角英数字で入力してください」 |
| パスワード | 必須、最大255文字 | 未入力時「パスワードを入力してください」 |
| パスワード確認 | 必須、パスワードと一致すること | 不一致時「パスワードが一致しません」 |

- 文字数上限は `m_user.login_id` / `password_hash` の `VARCHAR(255)` 定義（[db.md](../db.md)）に合わせる。ログインIDの文字種制約も同ファイルを参照。
- フロントエンドでは必須・文字数上限・文字種・パスワード確認の一致のみを検証し、ログインIDの重複有無の判定はAPI（`POST /auth/signup`）に委ねる。

## 8. 状態遷移

- **初期表示**：フォーム入力可能、サインアップボタン活性。
- **送信中**：サインアップボタンをローディング表示にし、入力欄・ボタンを無効化して二重送信を防止する。
- **エラー（ログインID重複）**：フォーム上部に「このログインIDは既に使用されています」を表示し、入力可能状態に戻す（パスワード・パスワード確認欄は空にする）。
- **エラー（バリデーション）**：該当項目にエラーメッセージを表示し、入力可能状態を維持する。
- **成功**：JWTをHttpOnly Cookieに設定（自動ログイン）し、S02へ遷移するため、本画面上での状態保持は不要。

## 9. 画面遷移

- 登録成功 → S02 チャット履歴画面（`/chats`）。追加のログイン操作は挟まない（自動ログイン）。
- ログイン画面へのリンク押下 → S00 ログイン画面（`/login`）。
- 有効なセッション（JWT Cookie）を保持した状態で `/signup` にアクセスした場合 → サインアップフォームを表示せず、自動的にS02へリダイレクトする（S00と同様の挙動）。

## 10. APIとの入出力

対応API: [api.md](../api.md) の「サインアップ」（`POST /auth/signup`）

### リクエスト

```json
{
  "login_id": "string",
  "password": "string"
}
```

パスワード確認欄の値はフロントエンド内のバリデーションにのみ使用し、APIには送信しない。

### レスポンス（想定）

- 成功時（201）：ログイン成功時と同様にJWTをHttpOnly Cookieに設定。レスポンスボディは最小限とし、フロントはCookie設定を前提にS02へ遷移する。
- ログインID重複時（409）：

```json
{
  "message": "このログインIDは既に使用されています"
}
```

- サインアップ機能が無効化されている場合（403）：

```json
{
  "message": "現在サインアップは受け付けていません"
}
```

フィールド名・ステータスコード等の詳細は実装時に確定し、[api.md](../api.md) との整合を取ること。

## 11. 権限制御

未ログイン専用画面。有効なセッションを保持するユーザーがアクセスした場合は、サインアップフォームを表示せずS02へリダイレクトする（8節・9節を参照）。

### サインアップ機能の有効・無効切替

サインアップ機能全体（S00のリンク表示、本画面へのアクセス、`POST /auth/signup` の受付）は、設定（環境変数等によるフラグ）で一括して有効・無効を切り替え可能とする。

- **無効時**：
  - S00にサインアップへのリンクを表示しない（[S00-login.md](./S00-login.md) 11節参照）。
  - `/signup` への直接アクセス時は、フォームを表示せずS00へリダイレクトする。
  - `POST /auth/signup` へ直接リクエストされた場合もAPI側で拒否し、403を返す（フロントのガードのみに依存しない）。
- フラグの具体的な設定方法（環境変数名等）は実装時に確定する。

## 12. その他実装上の注意事項

- パスワードのハッシュ化・保存方式はログイン機能（`m_user.password_hash`）と共通のものを用いる。
- ログインIDの重複判定はAPI側で行い、`m_user.login_id` の一意制約（[db.md](../db.md)）に依拠する。
- 登録直後の自動ログインは、ログイン失敗回数（`failed_login_count`）等のロック関連カウンタに影響を与えない。
