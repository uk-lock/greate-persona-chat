# S02 チャット履歴画面

## 1. 概要

| 項目 | 内容 |
|---|---|
| 画面ID | S02 |
| 画面名 | チャット履歴画面 |
| パス | `/chats` |
| 認証 | 必要 |

対応する画面一覧は [screen-list.md](../screen-list.md)、画面遷移は [screen-flow.md](../screen-flow.md) を参照。

## 2. 画面の目的

ログインユーザーが過去に作成したチャットの一覧を確認し、任意のチャットを開く、または不要なチャットを削除する。

## 3. 想定ユーザー

ログイン済みの全ユーザー。ログイン成功後の遷移先でもある（[screen-flow.md](../screen-flow.md) 参照）。

## 4. 表示内容

- チャット一覧（各行：タイトル、参加ペルソナ（肖像画像＋名前、複数）、最終更新日時）
  - `chat_mode` が `USER_PARTICIPATED` のチャットは、参加ペルソナの表示に「あなた」を加える（先頭に表示）。`PERSONA_ONLY` のチャットには表示しない。モードの違いはバッジ等では示さず、この「あなた」の有無のみで区別する。
- 各行の「Open」ボタン・削除ボタン
- チャットが1件もない場合の案内文言
- 共通サイドバー（[screen-list.md](../screen-list.md) 3節）

## 5. UIコンポーネント

| コンポーネント | 種別 | 備考 |
|---|---|---|
| チャット一覧 | list | 各行にタイトル・参加ペルソナ（複数、肖像画像＋名前）・最終更新日時を表示。最終更新日時の降順でソートする。`chat_mode` が `USER_PARTICIPATED` の場合、参加ペルソナの先頭に「あなた」を表示する |
| Openボタン | button | 各行に配置。クリックでS03へ遷移する |
| 削除ボタン | button（アイコン） | 各行に配置。クリックで削除確認ダイアログを表示する |
| 削除確認ダイアログ | modal | 「このチャットを削除しますか？」等のメッセージとOK／キャンセルボタン |
| 空データ案内 | テキスト | チャットが0件の場合に表示 |

## 6. ユーザー操作

- 一覧の任意の行にある「Open」ボタンを押すと、そのチャットのS03画面へ遷移する。
- 一覧の任意の行にある削除ボタンを押すと、削除確認ダイアログが表示される。
- ダイアログでOKを押すとチャットを削除する。キャンセルを押すと何もせずダイアログを閉じる。

## 7. バリデーション

本画面は閲覧・削除操作のみで入力フォームを持たないため、フォームバリデーションはない。削除は確認ダイアログによって誤操作を防止する。

## 8. 状態遷移

- **読込中**：画面表示時、チャット一覧取得中はローディング表示にする。
- **表示中**：取得したチャットを最終更新日時の降順で一覧表示する。
- **空データ**：チャットが0件の場合、案内文言のみを表示する（「Open」「削除」ボタンを含む一覧要素は表示しない）。
- **削除確認中**：削除ボタン押下時、確認ダイアログを表示し、背後の一覧操作を不可にする。
- **削除処理中**：ダイアログでOKを押した後、削除APIの完了までダイアログ内のボタンをローディング表示＋無効化する。
- **エラー**：一覧取得または削除に失敗した場合、エラーメッセージを表示する。

## 9. 画面遷移

- 各行の「Open」ボタン → S03 チャット画面（`/chats/{chat_id}`）
- 共通サイドバーから他画面（新規チャット／チャット履歴／ペルソナ一覧／ログアウト）へいつでも遷移できる（[screen-list.md](../screen-list.md) 3節）。
- S00 ログイン画面での認証成功後、本画面へ遷移する（[screen-flow.md](../screen-flow.md) 参照）。

## 10. APIとの入出力

対応API: [api.md](../api.md)

### チャット一覧取得

```http
GET /chats
```

レスポンス（想定）：チャットごとに `chat_id`・`title`・`chat_mode`・`updated_at`・参加者一覧（`participants`）を含む配列を、`updated_at` の降順で返す。

`participants` は以下の要素からなる配列とする。

- `chat_mode` が `USER_PARTICIPATED` の場合：先頭に `{ "type": "USER", "name": "あなた" }` を含め、続けてペルソナ（`t_chat_persona.sort_no` 順）を並べる。
- `chat_mode` が `PERSONA_ONLY` の場合：ペルソナのみを `sort_no` 順に並べる（`USER` 要素は含めない）。
- ペルソナ要素は `{ "type": "PERSONA", "persona_id": number, "name": string, "image_url": string | null }`。

### チャット削除

```http
DELETE /chats/{chat_id}
```

削除確認ダイアログでOKが押された際に呼び出す。成功時、一覧から該当チャットを除去する（`t_chat.is_deleted` による論理削除。[db.md](../db.md) 参照）。

フィールド名・ステータスコード等の詳細は実装時に確定し、[api.md](../api.md) との整合を取ること。

## 11. 権限制御

ログイン必須画面。未ログイン状態でアクセスした場合はS00へリダイレクトする。一覧・削除操作の対象は、ログインユーザー自身が作成したチャット（`t_chat.user_id` が一致するもの）に限る。他ユーザーのチャットは表示・操作できない。

## 12. その他実装上の注意事項

- 「最終更新日時」には `t_chat.updated_at` を用いる。メッセージ送信のたびに `t_chat.updated_at` が更新される実装とすること（メッセージ送信APIについては [api.md](../api.md) 参照）。
- MVPでは一覧を全件取得・表示する方針とし、ページングや無限スクロールは対象外とする。件数増加時の対応は将来検討する。
- 「あなた」はAPIレスポンス側（`GET /chats`）で、`chat_mode` が `USER_PARTICIPATED` の場合に参加者一覧の先頭要素として付与する（10節参照）。フロントは受け取った参加者一覧をそのまま表示すればよい。
